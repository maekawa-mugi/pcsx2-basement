# Hardware texture interpolation (experimental)

The hardware renderer now has two independent controls:

- **Texture Filtering Mode** (the existing `filter` option): Nearest, Forced, Follow PS2, and Forced Except Sprites. The stored values are unchanged and the setting is shared with the software renderer.
- **Interpolation Method** (`TextureInterpolation`): Bilinear (0, default), Bicubic/Catmull-Rom (1), and windowed Jinc (2). This option only affects the classic hardware renderers.

The kernel is selected **after** the original PS2/forced/nearest decision. Nearest always wins. For ordinary colour textures, bicubic and Jinc use a 4x4 nearest-tap reconstruction in the TFX pixel shader; texture wrap and clamp still come from the original sampler state. The existing bilinear path is unchanged by default.

To avoid altering accuracy-sensitive emulation, non-bilinear interpolation falls back to the original sampling path for palette/depth formats, texture shuffle, special wrap/region handling, framebuffer reads, hardware mipmapping/trilinear filtering, and anisotropic filtering. This initial implementation therefore does not apply the new kernels to all 3D surfaces. They require 16 taps per sampled pixel and can be substantially slower, especially at high internal resolutions.

The wider kernels require a completely uploaded base texture layer. Hash-cached textures and complete local-memory sources qualify; partially uploaded sources, render-target sources, and temporary hazard copies retain the original sampling path. The cache and hazard coverage still assume bilinear filtering, so expanding the supported source types requires changes to those coverage calculations first. With texture preloading disabled or large textures that cannot be preloaded, the new kernels may therefore fall back to bilinear until the entire base layer is uploaded.

The implementation covers Vulkan, OpenGL, Direct3D 11/12, and Metal. Software and parallel-GS renderers are not changed.

## Validation checklist

- Compare Bilinear/default mode with the base branch across representative games and GS dumps.
- Test nearest, follow-PS2, forced, and forced-except-sprites modes independently from the interpolation selector.
- Compare sharp/soft edges, alpha textures and repeat/clamp borders for bicubic and Jinc.
- Verify correct fallbacks for palette, depth, render-target sampling, mipmapped 3D textures and anisotropy.
- Check shader compilation on Vulkan, OpenGL, D3D11, D3D12 and Metal and compare performance.
- Check global and per-game configuration persistence.

Windows Release builds, representative Vulkan/OpenGL/D3D shader compilation, and base-layer completeness regression tests have been checked locally. Real-game/GS-dump validation, performance measurements, and Metal/Linux/macOS compilation still need proper testing.

## Vulkan Jinc AR and trilinear

Vulkan Jinc now uses the verified imgview LUT generated by `tools/generate_lut.cpp`:
`q = r / 0.9812505644269356`, `Jinc(pi*q) * Jinc(pi*q/3)`, with
`Jinc(x) = 2*J1(x)/x`, `Jinc(0) = 1`, and support `3.2383154841662362 * 0.9812505644269356`.
The embedded 1024 coefficients and linear LUT interpolation replace the old eighth-order approximation.
The footprint is deliberately limited to 4x4 (offsets -1 through 2); this truncates imgview's
8x8 footprint and is not numerically identical to its full reconstruction. Weights are normalized
over the selected 16 taps. Full-strength anti-ringing clamps all RGBA components to the extrema
of the central 2x2 samples, reusing those taps without extra texture fetches.

For Vulkan Jinc, the earlier mipmapping fallback is lifted for complete local-memory/hash-cache
sources. Each chosen mip is reconstructed and clamped separately, then adjacent mip colours are
blended using fractional LOD for linear mip filtering. Nearest mip modes retain nearest mip
selection. Manual LOD keeps the existing GS LOD calculation; generated mipmaps use screen-space
derivatives. Integer LOD needs 16 taps; fractional LOD needs at most 32. All manually uploaded
mip levels must be complete, and invalidation restores fallback. Anisotropy and the other
source/format/hazard fallbacks still apply. Other backends retain their existing Jinc implementation.

To compare, select Vulkan, Jinc, mipmapping on, and anisotropic filtering off. Select Trilinear
(PS2) to preserve the game's mip choice, or Forced to exercise generated mipmaps as well.
AR is always enabled for Vulkan Jinc. MGS3 image quality and speed still require game validation.

The coefficient LUT is uploaded once to a shared 1024x1 R32F texture. Jinc draws reuse
the otherwise unused palette descriptor; actual palette draws retain their original binding.
On devices supporting linear filtering of R32F, one hardware-filtered sample uses imgview's
`(r/support*1023 + 0.5)/1024` texel-centre coordinate. This halves LUT sampling instructions:
16 per mip, at most 32 for trilinear, in addition to the unchanged colour taps. Devices without
that Vulkan format capability retain the two-read interpolation fallback. Palette draws use
texelFetch with a point sampler and preserve their original addressing.
Do not put a dynamically indexed 1024-element constant array back in the shader: SPIR-V
lowered both LUT reads to local array copies, creating excessive private storage and potential
driver compilation/execution costs. Real-game stall and performance testing is still required.

The hardware-linear LUT matched the manual LUT capture within one RGBA code value on Intel
UHD 770 at 3x resolution. Three alternating 160-frame synthetic runs had median wall times of
3.031 seconds (manual) and 2.578 seconds (hardware-linear), including startup and GPU drain.
This is a synthetic measurement; MGS3 frame rate has not been measured.
